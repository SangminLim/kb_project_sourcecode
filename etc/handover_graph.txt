=============
1. Multi Step Reasoning
장애현황과 청구 이용내역은 단순 조회가 아니라
조회 → 검증 → 요약 → 영향도/이상징후 판단 순서로 처리했습니다.

장애현황은 상태, 경과시간, 심각도, 고객영향, 조치정보를 기준으로
우선순위와 권장조치를 산출하고,
청구 이용내역은 월별 금액을 조회한 뒤 전월 대비 증감률과 이상징후를 판단합니다.
2. RAG 구성
업무 문서를 의미 단위로 청킹하고,
system_id, intent, section_id 같은 메타데이터를 함께 부여했습니다.

사용자 질문이 들어오면 intent와 system_id를 판단하고,
ChromaDB에서 관련 청크를 검색한 뒤
질문 + 검색 컨텍스트 + 시스템 프롬프트를 LLM에 전달해 답변을 생성합니다.
3. Context / Prompt
Context는 Vector DB에서 검색된 업무 문서 내용입니다.
Prompt는 답변 방식과 역할을 제어하는 지시문입니다.

즉 LLM에는 사용자 질문만 보내는 것이 아니라
시스템 프롬프트, 사용자 질문, 검색된 업무 컨텍스트를 함께 전달합니다.
4. Harness 검증
Harness는 에이전트가 의도대로 동작하는지 검증하기 위한 자동 평가 체계입니다.

질문 시나리오를 만들어
intent 분류, system routing, tool 호출, workflow 정상 동작,
Multi Step Reasoning 결과를 검증하도록 구성했습니다.
5. LangChain
LangChain은 LLM 호출, 프롬프트 구성, Retriever 연동 같은
기본 AI 애플리케이션 구성 요소에 사용했습니다.

즉 RAG를 구현하기 위한 LLM 호출과 검색 컨텍스트 연결에 활용했습니다.
6. LangGraph
LangGraph는 질문 유형별 Workflow 분기 처리를 위해 사용했습니다.

사용자 질문을 classify하고,
업무질문, 실시간 조회, SQL 분석, 배치 개발, 일반 fallback으로 route한 뒤
각 노드에서 필요한 처리를 수행하도록 구성했습니다.
7. Harness / LangSmith 차이
Harness는 사전에 정의한 질문 시나리오로 기능이 정상 동작하는지 검증하는 테스트 체계입니다.

LangSmith는 실행 과정에서 LLM 호출, Retriever 결과, 각 노드 처리 흐름을 추적하고
운영 중 디버깅과 품질 모니터링에 활용하는 도구입니다.
8. 배치개발 / SQL 분석
배치개발은 요청서를 기반으로 배치 유형을 분류하고,
Rule + Template 기반으로 배치 스펙과 소스 파일을 생성합니다.

SQL 분석은 요청서의 SQL, 수정내용, 운영정보를 파싱한 뒤
JOIN, GROUP BY, 파티션 조건, 인덱스 활용, FULL SCAN 가능성을
Rule 기반으로 분석하고 LLM이 설명을 보강합니다.
최종 한 문장
이 에이전트는 단순 RAG 챗봇이 아니라
RAG 기반 업무 질의, 실시간 DB 조회, Multi Step Reasoning,
SQL 분석, 배치 개발, Harness 검증, LangSmith 추적까지 포함한
업무형 Agent Workflow로 구성했습니다.

이 8개는 발표 전에 반드시 외워두는 게 좋아.

그냥 벡터 검색만 하면 이런 문제가 생김.

소득공제 업무 개요 물었는데 배치 흐름도 청크가 나옴
배치 프로세스 물었는데 리니지 청크가 나옴

발표용 답변

이렇게 말하면 돼.

쿼리 빌더는 자연어 질문을 바로 벡터 검색에 던지는 것이 아니라,
intent, system_id, section, step, job_id를 기준으로 검색 계획(QueryPlan)을 생성하는 계층입니다.

예를 들어 소득공제 배치 프로세스 질문은
system_id=소득공제, section=batch_process 조건으로 검색하고,
테이블 리니지 질문은 section=table_lineage,
장애현황 질문은 section=realtime_query와 query_id=today_incidents 조건으로 검색합니다.

이를 통해 업무 간 데이터 혼선을 줄이고,
질문 유형에 맞는 청크만 검색하도록 제어했습니다.
또한 단계나 배치ID 조건이 너무 강해 결과가 없을 경우
필터를 완화하여 재검색하는 fallback도 구성했습니다.

 HandoverAgent는 업무 인수인계 질의를 처리하는 핵심 Agent입니다.

사용자 질문이 들어오면 먼저 질문을 표준화하고,
LLM Rewrite를 통해 검색 가능한 질문으로 정리합니다.

이후 intent와 system_id를 판별하고,
intent에 따라 structured payload, graph_data, query_meta를 생성합니다.

업무 문서 질의는 system_id와 section 기반 Metadata Filter를 생성하여
ChromaDB에서 관련 청크를 검색하고,
검색 결과를 context로 구성해 LLM 답변을 생성합니다.

배치 흐름도와 테이블 리니지는 JSON 구조화 데이터를 graph_data로 반환하고,
장애현황과 청구 이용내역은 query_meta를 기반으로
별도 reasoning workflow로 분기합니다.

LangGraph workflow를 통해 prepare, rewrite, resolve, guard, retrieve, respond 단계를
명확히 분리했고, LangSmith tracing을 통해 실행 흐름 추적도 가능하게 구성했습니다.

이 패키지는 단순 RAG가 아니라,
질문 정규화 → intent/system 판별 → metadata filter 검색 →
context prompt 생성 → LLM 답변 또는 graph/table/chart 응답으로 분기하는
업무형 Handover Agent 엔진입니다.
